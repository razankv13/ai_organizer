# Code Style and Conventions

## Dart/Flutter Conventions

### Import Style
- **Always use package imports**: `import 'package:ai_organizer/...'`
- **Never use relative imports** within lib/ (enforced by linter)
- Order: Dart SDK → Flutter SDK → External packages → Internal packages

### Naming Conventions
- **Classes**: PascalCase (e.g., `NoteRepository`, `AIService`)
- **Files**: snake_case (e.g., `note_repository.dart`, `ai_service.dart`)
- **Variables/Functions**: camelCase (e.g., `notesProvider`, `getAllNotes`)
- **Constants**: camelCase or SCREAMING_SNAKE_CASE (linter allows both)
- **Private members**: prefix with underscore (e.g., `_database`, `_model`)

### Code Structure
- **Always declare return types** (enforced)
- **Prefer const constructors** where possible (enforced)
- **Use final fields** when values don't change (enforced)
- **Sort constructors first** in classes (enforced)
- **Avoid void async** - return Future<void> explicitly (enforced)

### Linting Rules (analysis_options.yaml)
Strict rules enforced:
- `unawaited_futures: error` - Must await or explicitly ignore futures
- `unrelated_type_equality_checks: error`
- `avoid_relative_lib_imports: error`
- `always_declare_return_types: true`
- `prefer_const_constructors: true`
- `prefer_final_fields: true`

Warnings:
- `always_use_package_imports: warning`

Ignored:
- `library_private_types_in_public_api: ignore` (needed for Riverpod/Freezed)
- `invalid_annotation_target: ignore` (needed for Freezed)

Disabled:
- `curly_braces_in_flow_control_structures: false`
- `constant_identifier_names: false`
- `non_constant_identifier_names: false`

### Code Generation
Files ending in `.g.dart` and `.freezed.dart` are auto-generated:
- **Never edit manually**
- Generated by `build_runner` for:
  - Freezed classes (`@freezed` annotation)
  - JSON serialization (`@JsonSerializable()`)
  - Drift database (`@DriftDatabase`, table classes)
  - Assets via flutter_gen

### Data Models
Use Freezed for immutability:
```dart
@freezed
class Note with _$Note {
  const factory Note({
    required String id,
    required String title,
    String? content,
  }) = _Note;
  
  factory Note.fromJson(Map<String, dynamic> json) => _$NoteFromJson(json);
}
```

### State Management Pattern
- **Data providers**: Return `AsyncValue<T>` or stream data
- **Action providers**: Expose methods for mutations, invalidate dependent providers
- **Example**:
  ```dart
  final notesProvider = StreamProvider<List<Note>>(...);  // Data
  final notesActionsProvider = Provider((ref) => NotesActions(ref));  // Actions
  ```

### Database Conventions
- Drift tables use PascalCase class names (e.g., `Notes`, `Tags`)
- Table columns use camelCase
- Use custom type converters for enums and complex types
- Migration strategy: increment `schemaVersion`, define `migration` callback

### Asset Management
- Use generated assets: `Assets.images.imageName` (type-safe)
- Translations in `assets/translations/` as JSON files
- Lottie animations: `Assets.animations.animationName`

### Environment Variables
- Use `.env` file (never commit)
- Load with `flutter_dotenv`
- Access via `dotenv.env['KEY_NAME']`

### Error Handling
- Use Riverpod's `AsyncValue` for async operations (loading, error states)
- Log errors appropriately
- Provide user-friendly error messages in UI
